# C2 
## Core Concepts 
- **listening post**: server that will publish tasks, receive results of those tasks
  - operator can use CLI to interact w/ listening posts 
- **implant**: program that runs on target computer, makes contact w/ server periodically to get tasks to perform; will execute those tasks and send back results
- **task**: ex. returning information about computer/network the implant is running on, executing OS commands, enumerating processes/threads, injecting into another processes, establishing persistence, stealing creds for lateral movement, etc.


## RainDoll notes (Basic Implant & Tasking) 

- tasks: 
  - ping: respond w/ pong message 
  - configure: set implant specific options (ex. running status, dwell time)
  - execute: run OS commands that are provided by user 
  - listThreads: list the threads in a given process 

- implant will talk to listening post

- multi stage implant chain: each stage can handle specific job (ex. persistence, C2 communication, data exfiltration) 
  - stage 0: initial payload, very small, decides which stage 1 to pull based on the environment
    - should be fileless, injected into memory; should disappear after execution  
      - so detecting this would require memory analysis, network forensics,  
  - stage 1: ex. full-featured loader, RAT, etc. setup persistence, stealth, data exfiltration, etc.  

- c2c sends tasks
  - each task has: 
    - uuid 
    - bag of key values that helps implant figure out how to do task
    - task type 

- implant sends results, receives tasks  
  - result has: 
    - uuid 
    - contents 
    - success: bool 

- beacon loop: logic that handles "beacons" (periodic check-ins) from an infected machine (implant, agent, etc.)
  - beaconing: comprimised machine contacts c2 server at regular/random intervals
    - ex. do you have any tasks?, will send back results of periodc commands
  - beacon loop in c2 server: 
    - 1) waits for incoming beacons from agents 
    - 2) identifies agent via session ID, IP, etc. 
    - 3) checks task queue for that agent 
    - 4) will send back any commands/says stand by 
    - 5) logs beacon incident

- implant's beacon loop: 
  - two threads simultaneously: 1) beacon thread (responsible for pushing results pulling threads) 2) service thread (executes tasks, sleep)
